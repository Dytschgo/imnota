# Documentation-only PR validation

Validate runs full application and platform checks for main-branch pushes and for every PR except a conservatively classified prose-only change. Nightly and stable workflows are unchanged.

The classifier accepts only ordinary non-executable files at `README.md`, `AGENTS.md`, or under `docs/` with a lowercase `.md` extension. Nested directory and file names allow letters, digits, underscores, and hyphens. Spaces, unusual paths, other document locations, workflow/configuration changes, symlinks, executable-bit changes, mixed changes, or uncertain classification retain full checks. These paths are not TypeScript/Vite inputs or electron-builder package inputs, and no repository build/runtime script reads them. Revisit this policy if that changes.

The classifier compares the exact PR base and head commits using NUL-delimited raw Git output, with rename detection disabled. Moving source into a document therefore still exposes the source deletion. A base branch that has advanced can cause extra full validation; the classifier deliberately tolerates this conservative result. Empty diffs, invalid hashes, absent history, Git errors, unexpected modes/statuses, and excessive diff output all select full validation.

Quality and share-service matrix checks retain their names. Validate package work reports separate build, walkthrough, clipboard, and macOS DMG jobs under each per-OS reusable workflow. `quality-checks` runs the existing quality checks; `quality` is the required aggregate of `quality-checks` and the three-OS `share-service` matrix, which also runs platform checks. Failed or skipped dependencies fail the aggregate. For prose-only PRs, package/service jobs report an explicit documentation-only step. Quality checks install the pinned dependencies and run the existing complete formatting check. CodeQL and dependency review continue unchanged. Application/native steps run when the classifier reports anything except successful `docs_only=true`, including a failed classifier job. Cancellation still cancels dependent work.

Formatting cannot establish whether prose, links, commands, or agent instructions are correct. Review those under [AGENTS.md](../AGENTS.md); the shortcut changes application CI work, not documentation review responsibilities.

`scripts/ci-changes.test.mjs` runs through the shared script-test command in full quality checks, every per-OS service/platform test job, and release suites. Its real Git fixture exercises CLI output and source-to-document renames; focused cases cover malformed, mixed, missing, and non-regular input. A configuration PR must pass full hosted checks. Verify a subsequent useful prose-only PR before claiming hosted routing savings, including the original required `quality` context and every matrix check result.

To restore full PR validation, remove the classifier conditions from Validate. No branch protection or release setting needs to change.

## Superseded runs and workflow linting

Validate and CodeQL use a concurrency group keyed by the pull request number, so a newer push to the same PR cancels the validation still running for the superseded revision instead of competing with it for runners. Main-branch pushes are keyed by commit and never cancel each other, so every merged revision is still validated in full. Before this change, one branch produced four complete eight-minute Validate runs within 25 minutes while its earlier revisions were already obsolete.

Quality also lints the workflow files with a pinned `actionlint` container before the application checks, so a workflow expression, unknown input, or shell mistake fails the PR instead of the first run that happens to reach it. The container's bundled shellcheck runs at warning severity: style hints stay advisory rather than blocking a release workflow nobody is editing.

## Pinned actions, time limits, and least privilege

Every action in the workflows is pinned to a full commit SHA with its release version in a trailing comment, and the `actionlint` container is pinned by image digest as well as tag. A moved or compromised tag therefore cannot change what a release workflow executes. Dependabot's `github-actions` updater rewrites both the SHA and the version comment; it does not update the container reference inside the `run` step, so bump that tag and digest together by hand. Validate, CodeQL, nightly, and stable use the same version of each action. Nightly and stable previously ran older `pnpm/action-setup` and `actions/setup-node` majors than the PR checks that validated the same commands, and paired `actions/upload-artifact` v7 with `actions/download-artifact` v4.

Every job has a `timeout-minutes` limit so a hung step fails within minutes instead of holding a runner for the six-hour default. Recent main runs measured package jobs at 5 to 10 minutes, quality at about 2.5 minutes, each share-service job under a minute, and CodeQL at 1 to 2 minutes. Validate package limits are 30 minutes for builds, 20 for the standard walkthrough and DMG jobs, and 15 for clipboard jobs (walkthroughs retain their [six-minute launcher deadline](verification-timing.md#september-26-packaged-smoke-budget)); other limits are 30 for CodeQL, 20 for quality checks and combined service/platform jobs, 5 for the required quality aggregate, 10 for dependency review, and 5 for classification. Nightly retains its 45-minute package and 20-minute quality limits, with 30 minutes for publication and 10 for its guard; [stable limits](stable-release-ci.md#parity-with-nightly-gates) are recorded with that workflow. A classifier that times out does not report success, so the dependent jobs run full validation.

Quality runs `scripts/secret-scan.mjs` on every PR, including documentation-only ones, because prose can carry a pasted credential. Dependency review keeps only `contents: read`; it posts no PR comment, so `pull-requests: write` was unnecessary. Dependabot now also opens version updates for `share-service/`, whose separate lockfile previously received only security updates.

## Parallel application verification

The existing three-OS `share-service` matrix runs every script test followed by Vitest with `vitest.platform.config.ts` (the same discovery as `test:platform`), and runs `test:share-contract` using the service dependencies already installed for security checks. Scripts run first so their existing Windows PowerShell checks exercise the native runtime before Vitest's timed file-lock reader on a fresh runner. Test timeouts remain unchanged; no retries are added. These checks run alongside packaging instead of serially between packaging and the native walkthrough. The contract suite uses real HTTP, SQLite and filesystem fixtures, so all three OS executions remain. Quality checks retain their own contract run.

The macOS updater script has one native case that requires the actual universal packaged ZIP. The macOS package job therefore also runs `node --test scripts/update-macos.test.mjs` with `IMNOTA_REQUIRE_MAC_UPDATE_TEST=1`, which rejects a missing package instead of silently skipping that case. The source-only platform job exercises the remaining script cases. No test discovery policy or test file changes as part of this workflow change.

Quality checks run the full application suite once with coverage, then the existing script-test command. Both fail on test failures. Coverage percentages have no thresholds; report retention stays diagnostic. The `quality` aggregate fails unless both quality checks and every service/platform job succeed, so moving the platform tests cannot bypass the strict branch-protection context. Service check names and the quality aggregate remain; package work is split as described below.

Platform checks reuse the existing service runners and their service installation, avoiding three additional queued jobs and duplicate service installs while removing source verification from the package critical path. Service security still runs on Node 24 before application/platform verification on Node 22. The service dependencies are JavaScript packages, with no Node-version-specific native build to reinstall. Existing lockfile-keyed pnpm caches remain. The [Electron archive-cache experiment](history/build-cache-experiment.md) found no Windows/Linux savings and restore costs exceeding observed download times; no additional download caches are introduced without new evidence.

Validate calls `validate-package.yml` once per OS. Each build uploads the exact portable Windows EXE, Linux AppImage, or universal Mac ZIP selected by the existing verifier. Its standard walkthrough and clipboard walkthrough then run on separate fresh runners with the same commands and clipboard environment as before. The launchers still create isolated profiles; no smoke or test script changes. Standard Windows verification also downloads the same build's unpacked application for MCP; the verifier's compiled fixture imports are built from the same checkout. AppImage consumers restore the executable bit lost in artifact transfer.

Windows Validate builds use `compression=store`; Linux Validate builds use `deb.compression=gz`. These command overrides apply to both PRs and main pushes, without changing shared package configuration. Mac builds produce only the universal ZIP; a parallel Mac job extracts that ZIP and builds the DMG with electron-builder's `--prepackaged` option. A DMG failure fails Validate. The DMG remains a review artifact under `imnota-macos-dmg`.

All build, native, clipboard, updater/rollback, Windows visual, and evidence checks remain. The new jobs retain the existing package gating policy: package jobs were outside the required `quality` aggregate and remain so; failures in any reusable-workflow job fail Validate and its per-OS package result. They have no `continue-on-error`. `quality` still strictly requires quality checks and all service/platform checks; classification and its fail-safe expression are unchanged. Evidence uploads use `!cancelled()` to retain failures without prolonging cancelled runs.

Nightly and stable retain their existing commands, compression (including Windows LZMA), DMG builds, serial walkthroughs, and publication gates. Nightly still verifies the shipped compressed Windows artifact. Revert the Validate workflow split and its reusable workflow to restore the previous scheduling; no release or application-data migration is involved.
